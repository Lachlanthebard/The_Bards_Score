# Contributing to Bard's Score

Thank you for helping improve Bard's Score.

1. Open an issue describing a bug or proposed feature before undertaking a major rewrite.
2. Fork the repository and create a focused feature branch.
3. Preserve existing notation, BSC file compatibility, and the pinned Momentum build unless a change is discussed.
4. Submit a pull request with a clear description, screenshots when UI changes, and relevant build output.
5. Test on the pinned Momentum revision; describe any Flipper hardware testing performed. Do not claim hardware testing unless it was performed.
6. Keep changes small and avoid introducing warnings: the build treats compiler warnings as errors.

**Maintainer approval is required before merging.** The maintainer also keeps a separate personal edition; not every proposed feature will necessarily be incorporated.

**Licensing:** The repository owner must choose and add a LICENSE file before contributions are accepted under a defined open-source license. Contributors should agree to the chosen license before submitting code.
